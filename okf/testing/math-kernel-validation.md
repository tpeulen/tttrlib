# `modules/math` — validation register

Every kernel in `modules/math` has been A/B-tested against an **independent**
reference implementation — sklearn, scipy, scikit-image, numpy, hmmlearn,
filterpy, Random123 / pcg32 known answers. The A/Bs are permanent tests, not
one-off scripts, and each header carries a `// Validation: A/B-TESTED <date>
-- ...` block after its include guard that names the reference and the test.
This file is the register those blocks point at.

Rule applied (user, 2026-08-11): *a method reimplemented in-tree is A/B'd
against the reference implementation and the A/B is kept as the acceptance
test.*

**ChiSurf is not a reference (user, 2026-08-19: "no chisurf as ref, not
stable").** It is a moving target that this library is also the upstream of,
so "the two agree" says only that two things which change together still
agree — and where a kernel began as a port of it, "bit-exact with ChiSurf" is
a statement about a snapshot, not about the mathematics. Every row that rested
on ChiSurf has been replaced by the upstream that was already checking the
same claim (scipy, scikit-learn, filterpy) and the ChiSurf tests are deleted,
not merely demoted. Being a port of ChiSurf is a fact about a kernel's
history; it is not evidence that it is right.

## How to run

```bash
python -m pytest test/python/misc/test_math_ab_clustering.py \
                 test/python/misc/test_math_ab_imaging.py \
                 test/python/misc/test_math_ab_probabilistic.py \
                 test/python/misc/test_math_ab_numerics.py
# 72 tests, 597 subtests, ~17 s on 2026-09-08. Reference libraries are optional
# imports; a missing one skips its class visibly. test_math_ab_numerics.py
# compiles test/cpp/ab_numerics_harness.cpp once (skips without a compiler).
```

Recorded references: `test/data/reference/math_ab_clustering_reference.npz`
(the `hdbscan` package, generated by
`test/python/misc/gen_math_ab_clustering_reference.py`; the reference venv must
inherit the *working tree's* tttrlib — `uv venv … --system-site-packages` — or
pip resolves a release that predates these kernels and the generator fails on
the missing attribute rather than recording a different tree),
`test/data/reference/math_ab_probabilistic_reference.npz`
(hmmlearn 0.3.3 + filterpy 1.4.5, generated by
`test/python/misc/gen_math_ab_probabilistic_reference.py` in a scratch venv so

outputs), and the pre-existing `watershed_skimage_reference.npz`,
`kmeans_chisurf_reference.npz`, `kalman_chisurf_reference.npz`.

## What the A/B found

* **UMAP's spectral initialisation stalled, and only the end-to-end A/B showed
  it (2026-09-24).** Every per-stage check passed (graph, a/b), yet UMAP +
  HDBSCAN on a two-band FLIM image segmented worse than umap-learn; from
  umap-learn's own spectral init tttrlib's SGD did *better* (ARI 0.95), which
  put the fault in the eigensolver. On path-like graphs the eigenvalues next
  to 1 sit ~1e-4 apart. The first solver restarted Lanczos from one vector and
  never converged, silently falling back to a random start; the thick-restart
  rewrite still stalled (residual 1e-3 after 300 cycles) because it
  orthogonalised the Krylov continuation against the *kept* Ritz vectors
  instead of the full basis. A numpy prototype showed the fix before the C++
  change (1e-11 after 2 cycles). `umap_spectral_layout` is now exposed and
  held to umap-learn's `spectral_layout` column for column. Lesson: a
  stochastic pipeline's quality claim is a distribution — umap-learn itself
  fails 3 seeds of 8 on that image — so the segmentation test compares eight
  seeds, not one.

* **`Random.h` PCG engine was not PCG.** `pcg_deterministic_u32` wrote the
  xorshift as `((state >> 18) ^ (state >> 27)) >> 27`; XSH-RR is
  `((state >> 18) ^ state) >> 27`. The pre-rotation word had 19 live bits, so
  every output had 13 zero bits in a rotating window and per-bit P(1) was
  0.22–0.37. Fixed 2026-08-17 (one token). Reach: `TTTR_RNG_ENGINE=pcg`, and the
  engine `selected_engine()` picks when `TTTR_RNG_DETERMINISTIC` is off with no
  engine named — never the Philox default, so no recorded fixture depended on
  the old stream. The Python binding needs a rebuild to pick the header change up.
* **`Random.h` `mt19937` was a name without an engine** — every streaming draw
  was Philox whatever the env said. Implemented 2026-08-17 (std::mt19937, numpy
  RandomState-identical); `deterministic` keeps its documented Philox fallback.
* **HDBSCAN vs sklearn end to end differs only on MST ties** — sklearn sorts
  its MST with unstable `np.argsort`, so equal-weight edges merge in an
  irreproducible order; feeding either side's tree to the other's downstream is
  exact, 54/54 over both selection methods. Not a kernel difference; tttrlib's
  total edge order is the reason its own answer is reproducible.
  **Leaf selection is where it shows.** It cuts the tree into many small
  clusters, so a single differently-broken tie moves a whole fragment: one
  in-tree set lands at ARI ≈ 0.5 end to end while the kernels are exact on a
  shared tree. Corroborated independently 2026-09-08 by a session classifying
  smFRET bursts, which compared its own pipeline against sklearn end to end over
  45 cases per method and got excess of mass ARI ≥ 0.963 (mean 0.994) against
  leaf ≥ 0.884 (mean 0.990) — the asymmetry the tie explanation predicts and a
  missing-noise-label explanation does not. If you compare labels against
  sklearn's, compare through one tree or expect this.
  **It is not a dimension effect**, which was the open question when those
  numbers arrived (their cases were 3-D, the in-tree sets mostly 2-D). Measured
  2026-09-08 on standardised blobs + noise, 6 seeds each, `min_cluster_size=20`,
  `min_samples=10`: tied MST weights *fall* with dimension — 28, 19, 14, 12, 8
  at d = 2, 3, 5, 8, 16 — and both methods stay at ARI ≥ 0.99 at every one of
  them. What drives the divergence is how fragmented the partition is, which is
  why leaf shows it: the 0.5 case is a set where leaf cuts to 6–7 clusters, and
  a single flipped tie moves one of them. A leaf run that returns few clusters
  is no more exposed than an excess-of-mass one.
* **The MST's endpoint orientation was a second, silent source of the same
  disagreement**, found 2026-09-08 while closing the selection gap. An MST edge
  is undirected, but the single linkage reads `source`/`target` as left and
  right, and left/right decides the order the condensation numbers its clusters
  — so the same tree handed over with the endpoints swapped gave the same
  partition under different cluster ids. `mutual_reachability_mst` now
  normalises to `source < target` in the same pass that sorts the rows.
* **Persistence is not a purity signal, and this repository's documentation
  said it was.** When `hdbscan_cluster_stability` was added 2026-09-08 the
  motivation written into four files — header, binding docstring, module README,
  changelog — was that persistence tells a real population from the leftover
  overlap between two. That came from the requesting agent's hypothesis and was
  never measured. It is false: two overlapping populations are one density mode
  and persist as one, which is exactly why excess of mass merges them. Measured
  on simulated two-population FRET tables (three separations × three seeds), the
  merged 50 %-pure cluster scored 0.45–0.66 against 0.44–0.46 for a genuinely
  pure population — the mixture at the *top* of the ranking, no threshold
  separating them. The question does have an answer in the condensed tree: the
  merged cluster has *cluster children* and the pure one has none, 12/12. Both
  results are pinned in `test_hdbscan_post_mst.py::TestWhatPersistenceDoesAndDoesNotSay`
  so the claim cannot creep back in.
* **`quadpr_bound` is not KKT-correct**, as its header already says, and the
  A/B pins the shape of that: equal to scipy whenever the sweep lands on a KKT
  point, feasible and never below the true minimum otherwise.
* **Two references are not references.** `skimage.restoration.wiener` is a
  different estimator from `wiener_deconvolve` (Laplacian-weighted balance,
  circular grid); ChiSurf's `mem.py` returns a value and a gradient of two
  different objectives. Both documented in the test docstrings rather than
  compared with a loose tolerance.
* **k-means `tol` differs from sklearn's** (Frobenius shift vs squared shift
  scaled by variance); the comparison runs both to strict convergence.
* **NNLS `x` is non-unique** on ill-conditioned / underdetermined designs
  (raw diffs up to 3e5 while residuals agree to 1e-10 and KKT holds); those
  cases pin residual + KKT only.
* **scipy's bounded Nelder-Mead stalls** short of the constrained optimum on
  both bounded cases; ours reaches it. Reference quirk.
* SWIG `VectorDouble` results (`r.p`, `maxent_invert`) must be copied while the
  owning result is alive — `np.asarray(f(...).p)` on a temporary produced
  garbage. Binding footgun, not a kernel issue.

## Keeping this current

A new kernel in `modules/math` gets a row here, a `// Validation:` block in its
header, and a test in the matching `test_math_ab_*.py` before it is called
done. If a kernel changes so a row's metric no longer holds, the test fails —
update the row with what changed and why, or fix the kernel; never loosen the
tolerance to make it pass.
